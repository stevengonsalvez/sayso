## Research Question

Build Sayso as a polished macOS notch dictation and desktop-control app with full user-facing parity with [Just Speak To It](https://github.com/crmitchelmore/justspeaktoit) and [jev-use](https://github.com/savka777/jev-use), while retaining local Indian-language dictation, the Sayso visual language, and the requested notch and floating surfaces.

## Executive Summary

Sayso now has a real macOS notch and floating surface, local English dictation, installed and verified offline Punjabi transcription, a local-model integrity pipeline, a configurable dictation hotkey, output safety controls, basic history, and a deliberately narrow grounded desktop-control flow. It is not yet full parity with either reference: Just Speak To It remains ahead in provider breadth, voice editing, history and output hardening; jev-use remains far ahead in candidate-based multi-step desktop control, hands-free control, wake phrases, and observed-effect recovery.

Recommended build order: port Jev's closed action loop and candidate-only decision flow first, then port Just Speak To It's safe voice-edit and output revalidation flows. Paid cloud transcription providers come after local and control paths are fully proven, because they add credentials, privacy consent, provider lifecycle, and cost surfaces.

## Key Findings

- Sayso's notch placement, collapse behaviour, and floating alternative are custom product surfaces, not copied generic HUD behaviour.
- Sayso's local Punjabi engine now downloads checksum-pinned artifacts and produced Gurmukhi text from a transient Punjabi WAV fixture without Apple Speech.
- Sayso supports local English and nine FluidAudio Indian-language routes in source. Punjabi uses an independent Sherpa ONNX route. Only English and Punjabi have actual downloaded-model proof so far.
- Just Speak To It has a much broader transcription and TTS provider catalogue, robust output revalidation, richer history, personal corrections, and spoken editing orchestration.
- jev-use has a complete accessibility-tree control loop: read candidates, choose a closed action, act, re-read, and stop on completion, uncertainty, cancellation, or lack of observed effect.
- Current Sayso control intentionally supports only exact, grounded deterministic actions. It cannot yet claim comprehensive desktop control.

The project is MIT licensed.

### Current Sayso desktop-control boundary

Sayso is safe but intentionally constrained. It captures accessibility candidates, rejects secure and protected controls, uses bounded traversal, requires exact titles or explicit URLs, and asks for confirmation before destructive steps. [Candidate capture](https://github.com/stevengonsalvez/sayso/blob/0a5e8e5/macos/Sources/SaysoCore/AXCandidateCapture.swift), [planner and executor](https://github.com/stevengonsalvez/sayso/blob/0a5e8e5/macos/Sources/SaysoCore/DesktopControl.swift), and [session budgets](https://github.com/stevengonsalvez/sayso/blob/0a5e8e5/macos/Sources/SaysoCore/ControlSession.swift) support that claim.

It does not yet provide comprehensive desktop control. It has no multi-step planner, no candidate-choice model, no app-name resolution, no menu action system, no window arrangement, no wake phrase, no control hands-free loop, and no observed-effect proof for open, activate, or quit.

### Permissions and runtime findings

The latest Apple Development signed package has a stable designated requirement, one live Sayso process, and AVFoundation reports microphone `authorized`. The previous stuck UI was caused by a stale ad-hoc TCC code requirement from earlier local builds. Resetting only Sayso's microphone TCC record caused the new stable identity to register correctly.

Speech Recognition is currently `undetermined`. This is expected for local English and Punjabi paths, which do not require it. It remains needed for Apple Speech.

## Recommendations

1. Port jev-use's accessibility candidate capture, closed action schema, and observed-effect loop before any broad cloud-provider work.
2. Port Just Speak To It's VoiceEditOrchestrator and output revalidation next, preserving Sayso's notch-first UI.
3. Add one local model download/proof path for FluidAudio multilingual before advertising all nine Indian language routes as ready.
4. Add control-specific PTT, hands-free, wake phrase, cancellation, and visual execution status after the grounded loop exists.
5. Add cloud STT and TTS as opt-in Keychain-backed provider modules with explicit transmission consent and health checks.
